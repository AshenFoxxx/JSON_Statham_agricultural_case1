# Объяснение: Как работает расчет маршрутов

---

## Контекст

Проект должен ответить на четыре вопроса:

1. Какая продукция доступна на складе?
2. Какие заказы есть у покупателей?
3. Какой транспорт доступен?
4. Как оптимально распределить продукцию между транспортом и покупателями?

---

## Шаг 1. Сбор данных

Система собирает данные из трех источников:

### Продукция (Products)

```json
[
  {"id": "strawberry", "name": "Клубника", "stock_kg": 600, "max_delivery_hours": 6},
  {"id": "tomato", "name": "Томаты", "stock_kg": 900, "max_delivery_hours": 24},
  {"id": "cucumber", "name": "Огурцы", "stock_kg": 700, "max_delivery_hours": 18}
]
```

### Покупатели (Buyers)

```json
[
  {"id": "buyer-obninsk", "name": "Рынок Обнинск", "longitude": 54.5126, "latitude": 36.5927},
  {"id": "buyer-kaluga", "name": "Сеть Калуга", "longitude": 54.5293, "latitude": 36.2754}
]
```

### Транспорт (Vehicles)

```json
[
  {
    "id": "vehicle-a",
    "name": "Газель А",
    "capacity_kg": 800,
    "fuel_consumption_l_per_100km": 10,
    "fuel_price_rub_per_liter": 62,
    "max_trips": 2,
    "max_stops": 3,
    "available": true
  }
]
```

---

## Шаг 2. Запрос к Solver API

Данные отправляются на бэкенд:

```bash
curl -X POST http://localhost:8000/api/v1/plan \
  -H "Content-Type: application/json" \
  -d '{
    "products": [...],
    "buyers": [...],
    "vehicles": [...]
  }'
```

### Что происходит на бэкенде

1. Валидация — проверка наличия и корректности данных
2. Расчет расстояний — между фермой и каждым покупателем (по координатам)
3. Оптимизация — распределение продукции по транспорту с учетом:
   - Грузоподъемности каждого транспорта;
   - Ограничений по количеству рейсов и остановок;
   - Сроков годности продукции;
   - Запросов покупателей.
4. Расчет стоимости — с учетом расхода топлива и цены

---

## Шаг 3. Расчет расстояний

Расстояние между точками рассчитывается по формуле гаверсинусов:

```
distance = 2 * R * arcsin(√(sin²((lat2-lat1)/2) + cos(lat1) * cos(lat2) * sin²((lon2-lon1)/2)))
```

Где `R = 6371 км` — радиус Земли.

---

## Шаг 4. Оптимизация

Solver решает задачу распределения:

### Ограничения

- суммарный вес по маршруту <= грузоподъемности транспорта;
- количество рейсов <= max_trips;
- количество остановок <= max_stops;
- суммарный спрос покупателя <= доступный запас;
- время доставки <= max_delivery_hours.

### Целевая функция

Минимизация общей стоимости доставки:

```
total_cost = Σ(distance_km × fuel_consumption × fuel_price / 100)
```

---

## Шаг 5. Расчет стоимости

Формула линейная — пропорциональна расстоянию:

```
fuel_liters = (distance_km / 100) * fuel_consumption
fuel_cost   = fuel_liters * fuel_price
```

Пример:

```
distance = 45 км
consumption = 10 л/100км
price = 62 руб/л

fuel = (45 / 100) * 10 = 4.5 л
cost = 4.5 * 62 = 279 руб
```

## Ограничения

### Что не учитывается

- пробки и дорожные работы;
- погодные условия;
- ограничения по весу/высоте для мостов;
- таможня и границы;
- топливные станции по маршруту.

### Что можно улучшить

- интеграция с реальным OSRM API для точных расстояний;
- учет пробок в режиме реального времени;
- мульти-точечные маршруты (via points);
- учет времени работы покупателей.
