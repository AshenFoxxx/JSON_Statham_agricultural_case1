# Объяснение: Как работает расчет маршрутов

## Контекст {#kontekst}

Проект должен ответить на четыре вопроса:

1. Какая продукция доступна на складе?
2. Какие заказы есть у покупателей?
3. Какой транспорт доступен?
4. Как оптимально распределить продукцию между транспортом и покупателями?

## Шаг 1. Сбор данных {#sbor}

Система собирает данные из трех источников:

### Продукция (Products)

```json
[
  {"id": "strawberry", "name": "Клубника", "stock_kg": 800, "max_delivery_hours": 6},
  {"id": "lettuce", "name": "Салат", "stock_kg": 500, "max_delivery_hours": 10},
  {"id": "cucumber", "name": "Огурцы", "stock_kg": 1000, "max_delivery_hours": 18},
  {"id": "tomato", "name": "Томаты", "stock_kg": 1200, "max_delivery_hours": 24}
]
```

### Покупатели (Buyers)

```json
[
  {"id": "buyer-obninsk", "name": "Рынок Обнинск", "longitude": 36.5855, "latitude": 55.112},
  {"id": "buyer-kaluga", "name": "Сеть Калуга", "longitude": 36.2613, "latitude": 54.5138}
]
```

### Транспорт (Vehicles)

```json
[
  {
    "id": "vehicle-a",
    "name": "Газель А",
    "capacity_kg": 800,
    "fuel_consumption_l_per_100km": 10,
    "fuel_price_rub_per_liter": 62,
    "max_trips": 2,
    "max_stops": 3,
    "available": true
  }
]
```

## Шаг 2. Запрос к Solver API {#zapros}

Данные отправляются на бэкенд:

```bash
curl -X POST http://localhost:8000/api/v1/plan \
  -H "Content-Type: application/json" \
  -d '{
    "farm": {"name": "Хозяйство", "longitude": 36.6103, "latitude": 55.0969},
    "products": [...],
    "buyers": [...],
    "vehicles": [...]
  }'
```

### Что происходит на бэкенде

1. Валидация — проверка наличия и корректности данных;
2. Расчет расстояний — между фермой и каждым покупателем через OSRM API;
3. Оптимизация — распределение продукции по транспорту с помощью CP-SAT solver;
4. Расчет стоимости — с учетом расхода топлива и цены.

## Шаг 3. Расчет расстояний через OSRM {#osrm}

Расстояние между точками рассчитывается через OSRM API — сервис маршрутизации по реальным дорогам.

```bash
curl "http://router.project-osrm.org/route/v1/driving/36.6103,55.0969;36.5855,55.112?overview=false"
```

Ответ содержит:

- `distance` — расстояние в метрах;
- `duration` — время в секундах;
- `geometry` — геометрия маршрута.

В отличие от формулы гаверсинусов, OSRM учитывает реальные дороги, а не прямые линии.

## Шаг 4. Оптимизация через CP-SAT {#cp-sat}

CP-SAT (Constraint Programming - SAT) — решатель ограничений от Google OR-Tools. Использует edge-переменные O(n^2) вместо O(n!).

### Переменные модели

| Переменная | Тип | Описание |
|-----------|-----|----------|
| `x[v,t,i,j]` | Bool | Машина v, рейс t, ребро i->j (включая возврат на хозяйство) |
| `y[v,t,j]` | Bool | Покупатель j посещён в рейсе t |
| `z[v,t,j,pi]` | Int | Кг продукта pi покупателю j машиной v, рейс t |

### Алгоритм

1. `build_plan()` — `planning.py`:
   - Собирает координаты хозяйства и покупателей;
   - `fetch_matrix()` — OSRM Table API для матрицы расстояний;
   - `solve_plan()` — передаёт граф в solver;
   - Для каждого рейса `fetch_route()` — OSRM Route API для геометрии.

2. `solve_plan()` — `solver_cp_sat.py`:
   - Фильтрует `(buyer, product)` по времени доставки;
   - Строит `feasible_edges` — рёбра, где есть маршрут и время;
   - Создаёт `AddCircuit` для каждого рейса каждой машины с self-loops;
   - Связывает `arr` (время прибытия) с `hop_sec` и временем разгрузки;
   - Ограничивает `z` входящими рёбрами и сроком культуры;
   - Группирует одинаковые машины — симметричное breaking;
   - Ограничивает грузоподъёмность, запас, спрос;
   - Максимизирует `revenue - transport_cost`;
   - `solver.Solve()` с лимитом 25 с и `num_search_workers=8`.

3. Извлечение решения:
   - `shipment_kg` — агрегация `z` по `(product, buyer, vehicle)`;
   - `trips_map` — рёбра с `x > 0.5`;
   - `_path_from_farm()` — порядок покупателей по рёбрам;
   - `planning.py` — уточнение `arrival_hours` с учётом разгрузки;
   - `fetch_route()` — точная геометрия и стоимость.

### Ограничения

- `AddCircuit` — обход без подциклов, с self-loops для пропущенных узлов;
- `max_trips` от 1 до 3: следующий выезд после возврата; смена не длиннее 12 часов;
- `max_stops <= 5` — до 5 покупателей за выезд;
- Грузоподъёмность, запас, спрос, время доставки.

### Целевая функция

Максимизация прибыли:

```
profit = revenue - transport_cost
```

Где:

- `revenue` = сумма quantity_kg * price_per_kg по отгрузкам;
- `transport_cost` = сумма стоимости топлива по всем рейсам.

### Параметры решения

| Параметр | Значение | Описание |
|----------|----------|----------|
| `max_time_in_seconds` | 25 | Лимит поиска CP-SAT |
| `num_search_workers` | 8 | Потоки поиска |

### Статусы решения

| Статус | Описание |
|--------|----------|
| `optimal` | Доказан оптимум |
| `feasible` | Найден план, оптимум не доказан |
| `infeasible` | Нет допустимого плана |
| `not_solved` | Решение не выполнено (таймаут) |

## Шаг 5. Расчет стоимости {#stoimost}

Формула линейная — пропорциональна расстоянию:

```
fuel_liters = (distance_km / 100) * fuel_consumption
fuel_cost   = fuel_liters * fuel_price
```

Пример:

```
distance = 45 км
consumption = 10 л/100км
price = 62 руб/л

fuel = (45 / 100) * 10 = 4.5 л
cost = 4.5 * 62 = 279 руб
```

## Ограничения {#ogranicheniya}

### Что не учитывается

- пробки и дорожные работы;
- погодные условия;
- ограничения по весу/высоте для мостов;
- таможня и границы;
- топливные станции по маршруту.

### Что можно улучшить

- учет пробок в режиме реального времени;
- мульти-точечные маршруты (via points);
- учет времени работы покупателей;
- учет загрузки на хозяйстве.

Формальная модель переменных и ограничений — в разделе [Модель solver](/doc/explanation/solver).
