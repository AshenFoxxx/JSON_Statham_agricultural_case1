## Почему CLI, а не REST API?

### Текущий подход: CLI-инструмент

```bash
python main.py --from "55.7558,37.6173" --to "59.9343,30.3351"
```

**Почему:**

- Простота — нет необходимости в сервере, базах данных, аутентификации
- Однозначность — один запуск = один маршрут
- Лёгкость тестирования — можно запускать в CI/CD пайплайнах
- Подходит для хакатона — быстрее реализовать

**Когда стоит перейти на API:**

- Нужен веб-интерфейс для пользователей
- Требуется кэширование запросов
- Нужна история маршрутов
- Несколько клиентов одновременно

## Почему OSRM, а не Google Maps?

### OSRM Public API

**Плюсы:**

- Бесплатный, без API-ключа
- Open-source, можно свой сервер
- Данные OpenStreetMap (часто актуальнее Google в РФ)
- Простой HTTP API

**Минусы:**

- Нет гарантированного SLA
- Нет поддержки в продакшене
- Ограничения на частоту запросов

### Google Maps / Mapbox

**Плюсы:**

- Production-ready
- Детальная аналитика
- Поддержка

**Минусы:**

- Платный (от $5/1000 запросов)
- API-ключи и billing
- Зависимость от провайдера

## Почему Leaflet, а не другие библиотеки?

### Leaflet.js

**Плюсы:**

- Лёгкая (~40KB gzipped)
- Простой API
- Хорошая документация
- Open-source

**Минусы:**

- Меньше плагинов чем у Mapbox GL
- Нет 3D-карт

### Альтернативы

| Библиотека | Размер | 3D | Платная |
|-----------|--------|-----|---------|
| Leaflet | 40KB | ❌ | ❌ |
| Mapbox GL | 200KB | ✅ | ✅ |
| OpenLayers | 300KB | ❌ | ❌ |
| Google Maps | 150KB | ✅ | ✅ |

## Почему тёмная тема для карты?

Тёмная тема выбрана для:

1. **Визуальной привлекательности** — выглядит современно
2. **Экономии энергии** — на OLED-экранах пиксели не светятся
3. **Контраста** — синий маршрут лучше виден на тёмном фоне
4. **Стиля навигатора** — как в реальных GPS-устройствах

## Почему разделённые сервисы?

### Map + Docs

**Почему разделены:**

- Разные зависимости (requests vs flask)
- Разные lifecycle (CLI vs persistent server)
- Разные команды запуска
- Независимое масштабирование

**Почему не монолит:**

- Docs-сервис не нужен для работы маршрутизатора
- Docs обновляются редко, map запускается часто
- Разные команды разработки

## Почему Docker Compose, а не Kubernetes?

### Docker Compose

**Плюсы:**

- Простой конфиг (YAML, ~50 строк)
- Локальная разработка
- Нет необходимости в кластере

**Минусы:**

- Нет auto-scaling
- Нет self-healing
- Один хост

### Kubernetes

**Плюсы:**

- Auto-scaling
- Self-healing
- Multi-node

**Минусы:**

- Сложность (Helm, manifests)
- Ресурсы (minikube ~2GB)
- Overkill для 2 сервисов

**Вердикт:** Compose для разработки, K8s для продакшена.

## Почему markdown + YAML для документации?

### Markdown

**Плюсы:**

- Простой синтаксис
- Читается в raw-формате
- Конвертируется в HTML
- Git-friendly (easy diffs)

### YAML для TOC

**Плюсы:**

- Иерархическая структура
- Читаемость
- Легко добавлять новые страницы

### Альтернативы

| Инструмент | Плюсы | Минусы |
|-----------|-------|--------|
| MkDocs | Готовый, много тем | Extra-зависимости |
| Sphinx | Стандарт для Python | Сложный синтаксис |
| Docusaurus | React, красивый | Node.js ecosystem |
| Custom (наш) | Полный контроль | Нужно поддерживать |
