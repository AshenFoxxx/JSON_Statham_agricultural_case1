# Бэкенд: план поставок

Документ для фронтенда и его ИИ-ассистента. Бэкенд уже считает план и маршрут по дорогам. Фронт отправляет текущие данные формы и рисует ответ. Считать оптимум и расстояния на клиенте не нужно.

Папки репозитория:

- `backend` — план поставок (`:8000`) и позже CRUD.
- `frontend` — React-форма.
- `demo-map` — карта защиты: `GET /map/`.

## Кто что делает

Бэкенд принимает хозяйство, культуры, покупателей и машины. Координаты приходят с фронта. Часы, километры, топливо и линии маршрутов бэкенд считает сам и возвращает вместе с планом.

Фронт:

1. Даёт ввести или изменить эти данные. Для старта формы можно взять `GET /api/v1/demo`.
2. По кнопке «Рассчитать поставки» отправляет **текущее состояние формы** на `POST /api/v1/plan`. Часы и километры в это тело не кладутся.
3. Показывает таблицу отгрузок, рейсы, выручку, транспортные затраты, прибыль, остатки и потери. На карте каждый выезд — своя линия из `geometry`, точки — из `waypoints`.
4. Даёт поменять вход и нажать расчёт снова. Отдельного эндпоинта пересчёта нет: это тот же `POST` с новым JSON. Так закрывается демо, где одну машину помечают недоступной или меняют цену.

Имена (`name`) показываются человеку. Связка строк в ответе идёт по `id`, которые задаёт фронт.

## Запуск

Из папки `backend`:

```powershell
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Базовый адрес: `http://127.0.0.1:8000`. Схема запросов: `http://127.0.0.1:8000/docs`. CORS открыт для любого origin.

## Эндпоинты

| Метод | Путь | Зачем |
| --- | --- | --- |
| `GET` | `/health` | Проверка, что сервер жив. Ответ: `{"status": "ok"}`. |
| `GET` | `/api/v1/demo` | Пример тела запроса, чтобы заполнить форму. Сам по себе план не считает. |
| `GET` | `/api/v1/demo/fleet` | Сценарий для карты: 3 машины и 10 покупателей. |
| `GET` | `/map/` | Демо-карта. Рисует линии из ответа плана. |
| `POST` | `/api/v1/plan` | Расчёт плана и линий выездов. Тело — данные формы. Нужен интернет: расстояния идут в OSRM. |
| `POST` | `/api/v1/route` | Маршрут по уже заданному порядку точек. Для демо-карты. Продуктовый экран его не вызывает. |

## Тело `POST /api/v1/plan`

```json
{
  "farm": {
    "name": "Хозяйство Обнинск",
    "longitude": 36.6103,
    "latitude": 55.0969
  },
  "products": [
    {
      "id": "strawberry",
      "name": "Клубника",
      "stock_kg": 600,
      "max_delivery_hours": 6
    }
  ],
  "buyers": [
    {
      "id": "buyer-kaluga",
      "name": "Сеть Калуга",
      "longitude": 36.2613,
      "latitude": 54.5138,
      "orders": [
        {
          "product_id": "strawberry",
          "demand_kg": 250,
          "price_per_kg": 210
        }
      ]
    }
  ],
  "vehicles": [
    {
      "id": "vehicle-a",
      "name": "Газель А",
      "capacity_kg": 800,
      "fuel_consumption_l_per_100km": 15,
      "fuel_price_rub_per_liter": 60,
      "max_trips": 1,
      "max_stops": 3,
      "available": true
    }
  ]
}
```

Поля:

- `farm` — одно хозяйство: `name`, `longitude`, `latitude`. В ответе его точка имеет `id` = `farm`.
- `products` — минимум одна культура. `stock_kg` и `max_delivery_hours` больше 0. Лимит часов — только время в пути, не срок хранения на складе.
- `buyers` — минимум один покупатель, у него минимум один заказ. `longitude` и `latitude` обязательны. В заказах одного покупателя `product_id` не повторяется. `demand_kg` > 0, `price_per_kg` ≥ 0.
- `vehicles` — минимум одна машина. `capacity_kg` > 0, `fuel_consumption_l_per_100km` > 0, `fuel_price_rub_per_liter` ≥ 0. `max_trips` всегда 1: водитель выезжает со склада один раз и возвращается. `max_stops` от 1 до 5: сколько покупателей машина объезжает за этот выезд. `available: false` означает, что машина сломана и в план не войдёт. Отдельной цены за выезд нет: стоимость считается из километров маршрута и этих двух полей.
- `unload_seconds_per_kg` — секунды разгрузки на кг, по умолчанию 0. В срок культуры входит конец разгрузки на остановке. Погрузка на хозяйстве не входит. В демо стоит 2.
- Координаты везде в порядке долгота, широта. `id` культур, покупателей и машин уникальны внутри своего списка. Каждый `product_id` в заказе должен совпадать с `id` культуры. Id покупателя не может быть `farm`.

Если OSRM недоступен, ответ `502` и поле `detail`. План в этом случае не возвращается.

Неверное тело отвечает `422` и JSON с полем `detail`. План в этом случае не считается.

Полный рабочий пример без сокращений: `GET /api/v1/demo`.

## Ответ `POST /api/v1/plan`

`status`:

- `optimal` — план построен и доказан как лучший;
- `feasible` — план есть, но за лимит времени оптимум не доказан;
- `infeasible` — допустимого плана нет;
- `not_solved` — решатель не нашёл план.

`objective` сейчас всегда `maximize_profit`.

Деньги в рублях:

- `revenue` — сумма `quantity_kg * price_per_kg` по отгрузкам;
- `transport_cost` — сумма топлива по рейсам туда и обратно на хозяйство. У рейса `cost = (distance_km / 100) × расход × цена литра`;
- `profit` — `revenue - transport_cost`.

`shipments` — строка поставки: культура, покупатель, машина, килограммы. Несколько рейсов одной машины к одному покупателю с одной культурой уже сложены в одну строку.

`trips` — один выезд. В `stops` покупатели по порядку, время до конца разгрузки от выезда и килограммы выгрузки. `distance_km` — длина дороги, `cost` — топливо на эту длину, один раз за выезд. Суммарная `load_kg` не больше `capacity_kg`, число остановок не больше `max_stops`.

`waypoints` — точки этого выезда по порядку. Первая и последняя — `{ "id": "farm", "longitude", "latitude" }`, между ними покупатели. `geometry` — GeoJSON `LineString`, координаты `[долгота, широта]`. Несколько выездов — несколько линий.

`balances` — по каждой культуре из запроса:

- `shipped_kg` — сколько уехало;
- `leftover_kg` — `stock_kg - shipped_kg`, не уехало из-за спроса или нехватки машин;
- `loss_kg` — сколько килограммов нельзя доставить ни одному покупателю в срок даже при свободном транспорте. Это часть остатка, отдельная цифра.

`assumptions` — готовый текст допущений. Его можно показать на экране как есть.

`message` — короткая строка для статуса расчёта, не замена таблицам.

## Как устроен расчёт

Формулы, ограничения и числовой пример: [SOLVER.md](SOLVER.md).

Это нужно, чтобы подписи на экране не обещали лишнего.

Прибыль максимизируется. Культуру можно выгрузить только на остановке, куда она успевает: время прибытия не больше `max_delivery_hours`. Отсчёт срока начинается в момент отправки. Время на складе и момент сбора не моделируются. Одна машина — один выезд. Вместимость — в килограммах на весь выезд. Машина с `available: false` пропускается.

Склад и ERP бэкенд не делает. Для демо достаточно формы, кнопки расчёта, таблицы и карты. Смена цены или поломка машины — правка JSON и повторный `POST`.
